# Домашнее задание № 2: примитивная база данных

Консольная база данных на Python в процедурном стиле. Устанавливаемый пакет
называется `primitive_db`; команды `database` и `project` запускают один интерфейс.

Требуются Python 3.12 и uv версии 0.5 или выше.

## Запуск

После клонирования репозитория выполняйте команды из его корневой директории:

```sh
uv sync
uv run database
```

Также доступны совместимая команда из первого этапа и запуск модуля:

```sh
uv run project
uv run python -m primitive_db.main
```

`uv` создает `.venv` в директории проекта и устанавливает зависимости из
`uv.lock`. Для ручной активации окружения: `source .venv/bin/activate`.

## Управление таблицами

| Команда | Действие |
| --- | --- |
| `create_table <имя> <столбец:тип> ...` | Создать таблицу с указанной структурой |
| `list_tables` | Показать таблицы в порядке создания |
| `drop_table <имя>` | Удалить таблицу |
| `help` | Повторить справку |
| `exit` | Завершить программу |

Пример сеанса:

```text
***Процесс работы с таблицей***
Функции:
<command> create_table <имя_таблицы> <столбец1:тип> .. - создать таблицу
<command> list_tables - показать список всех таблиц
<command> drop_table <имя_таблицы> - удалить таблицу

Общие команды:
<command> exit - выход из программы
<command> help - справочная информация

>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool
>>>Введите команду: create_table users name:str
Ошибка: Таблица "users" уже существует.
>>>Введите команду: list_tables
- users
>>>Введите команду: drop_table users
Таблица "users" успешно удалена.
>>>Введите команду: drop_table products
Ошибка: Таблица "products" не существует.
>>>Введите команду: exit
```

Поддерживаются типы `int`, `str`, `bool`. Имя таблицы и имена столбцов должны
быть непустыми; столбцы задаются в формате `имя:тип` и не повторяются.
Названия чувствительны к регистру. Разбор команд через `shlex` поддерживает
кавычки, например `create_table "active users" "full name:str"`.

`ID:int` автоматически добавляется первым. Явный `ID:int` допускается и также
перемещается в начало. Другой тип `ID` или повторный `ID` — ошибка.
`create_table users ID:int` создает таблицу только с идентификатором.
При отсутствии явного `ID` нужно задать хотя бы один столбец.

Для пустой базы `list_tables` выводит `Таблиц пока нет.` Неизвестные команды,
ошибки аргументов и незакрытые кавычки вызывают сообщение и повторный запрос.
Пустой ввод повторяет запрос. Ctrl+C и конец ввода завершают программу
без traceback. Импорт модулей ничего не запускает.

## Хранение метаданных

Структура таблиц сохраняется в `db_meta.json` в **текущей рабочей директории**:

```json
{
  "users": ["ID:int", "name:str", "age:int", "is_active:bool"]
}
```

Отсутствующий файл означает пустую базу. После успешного создания или удаления
структура сразу сохраняется, поэтому следующий запуск из той же директории
видит изменения. Другой рабочий каталог означает отдельную базу.

Некорректные команды не меняют файл. Запись выполняется через временный файл
с последующей заменой, чтобы ошибка записи сохранила предыдущую версию.
Поврежденный JSON, неверная структура метаданных и ошибки файловой системы
завершают программу с сообщением и кодом `1`; успешный выход имеет код `0`.
`db_meta.json` исключен из Git. Одновременная запись из нескольких процессов
на этом этапе не поддерживается. Строки таблиц будут добавлены позднее.

## Проверка качества и сборка

```sh
uv run python -m unittest discover -s tests -v
uv run ruff check .
uv run ruff format --check .
uv build
uvx twine check dist/*
```

Сборка создает wheel и исходный архив в `dist/`. Twine проверяет метаданные
локально; публикация на PyPI не требуется.

## Установка собранного пакета

```sh
uv tool install dist/primitive_db-0.2.0-py3-none-any.whl
database
```

Это устанавливает команду в отдельное окружение инструмента. Если каталог
исполняемых файлов отсутствует в `PATH`, выполните `uv tool update-shell`
и перезапустите терминал. Для повторной установки используйте:

```sh
uv tool install --force dist/primitive_db-0.2.0-py3-none-any.whl
```

## Текущий этап

Выполнены разделы «Подготовка» и «База данных»: устанавливаемый пакет,
цикл команд через `prompt`, управление схемами таблиц и хранение в JSON.
Начальная версия с сообщением `DB project is running!` сохранена в истории Git.

- `src/primitive_db/__init__.py` — пустой маркер пакета.
- `src/primitive_db/main.py` — точка входа с шебангом и функцией `main()`.
- `src/primitive_db/engine.py` — справка, разбор команд и цикл программы.
- `src/primitive_db/core.py` — проверка схем, создание и удаление таблиц.
- `src/primitive_db/utils.py` — загрузка и сохранение JSON.
- `tests/` — проверки через стандартный `unittest`, без новых зависимостей.
- `pyproject.toml`, `.python-version`, `uv.lock` — настройки и зависимости.
- `.gitignore` — исключения для окружения, кешей и результатов сборки.
