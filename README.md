# Домашнее задание № 2: примитивная база данных

Консольная база данных на Python в процедурном стиле. Устанавливаемый пакет
называется `primitive_db`; команды `database` и `project` запускают один интерфейс.

Требуются Python 3.12 и uv версии 0.5 или выше.

## Запуск

После клонирования репозитория выполняйте команды из его корневой директории:

```sh
uv sync
uv run database
```

Также доступны совместимая команда из первого этапа и запуск модуля:

```sh
uv run project
uv run python -m primitive_db.main
```

`uv` создает `.venv` в директории проекта и устанавливает зависимости из
`uv.lock`. Для ручной активации окружения: `source .venv/bin/activate`.

## Управление таблицами

| Команда | Действие |
| --- | --- |
| `create_table <имя> <столбец:тип> ...` | Создать таблицу с указанной структурой |
| `list_tables` | Показать таблицы в порядке создания |
| `drop_table <имя>` | Удалить таблицу |
| `help` | Повторить справку |
| `exit` | Завершить программу |

Пример сеанса (справка при запуске сокращена):

```text
***Процесс работы с таблицей***
Функции:
<command> create_table <имя_таблицы> <столбец1:тип> .. - создать таблицу
<command> list_tables - показать список всех таблиц
<command> drop_table <имя_таблицы> - удалить таблицу

Общие команды:
<command> exit - выход из программы
<command> help - справочная информация

>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool
>>>Введите команду: create_table users name:str
Ошибка: Таблица "users" уже существует.
>>>Введите команду: list_tables
- users
>>>Введите команду: drop_table users
Таблица "users" успешно удалена.
>>>Введите команду: drop_table products
Ошибка: Таблица "products" не существует.
>>>Введите команду: exit
```

Поддерживаются типы `int`, `str`, `bool`. Имя таблицы и имена столбцов должны
быть непустыми; столбцы задаются в формате `имя:тип` и не повторяются.
Названия чувствительны к регистру. Разбор команд через `shlex` поддерживает
кавычки, например `create_table "active users" "full name:str"`.

`ID:int` автоматически добавляется первым. Явный `ID:int` допускается и также
перемещается в начало. Другой тип `ID` или повторный `ID` — ошибка.
`create_table users ID:int` создает таблицу только с идентификатором.
При отсутствии явного `ID` нужно задать хотя бы один столбец.

Для пустой базы `list_tables` выводит `Таблиц пока нет.` Неизвестные команды,
ошибки аргументов и незакрытые кавычки вызывают сообщение и повторный запрос.
Пустой ввод повторяет запрос. Ctrl+C и конец ввода завершают программу
без traceback. Импорт модулей ничего не запускает.

## CRUD-операции

| Команда | Действие |
| --- | --- |
| `insert into <имя> values (<значения>)` | Добавить запись с автоматическим ID |
| `select from <имя>` | Показать все записи через PrettyTable |
| `select from <имя> where <столбец> = <значение>` | Показать записи по условию |
| `update <имя> set <столбец> = <значение> where <столбец> = <значение>` | Обновить все совпадения |
| `delete from <имя> where <столбец> = <значение>` | Удалить все совпадения |
| `info <имя>` | Показать схему и количество записей |

После создания таблицы `users name:str age:int is_active:bool`:

```text
>>>Введите команду: insert into users values ("Sergei", 28, true)
Запись с ID=1 успешно добавлена в таблицу "users".
>>>Введите команду: select from users where age = 28
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei | 28  |    True   |
+----+--------+-----+-----------+
>>>Введите команду: update users set age = 29 where name = "Sergei"
Запись с ID=1 в таблице "users" успешно обновлена.
>>>Введите команду: delete from users where ID = 1
Запись с ID=1 успешно удалена из таблицы "users".
>>>Введите команду: info users
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 0
```

Правила ввода:

- Все значения обязательны и передаются в порядке столбцов, кроме `ID`.
  Для таблицы только с ID используется `insert into ids values ()`.
- Строки всегда заключаются в одинарные или двойные кавычки. Поддерживаются
  экранирование кавычек и обратной косой черты, пробелы и запятые внутри строки.
  Например: `insert into notes values ("A, B (where = set)")`.
- Целые числа вводятся без кавычек, допускается знак: `28`, `-2`, `+3`.
  Булевы значения — только `true` и `false` без кавычек.
- Типы проверяются строго: `"28"` не подходит для `int`, `1` — для `bool`,
  `true` — для `int`. Пустая строка `""` допустима для `str`.
- `WHERE` принимает одно равенство, `SET` — одно присваивание. `update` и
  `delete` применяются ко всем совпавшим записям. Неизвестные столбцы,
  неверные типы и неподдерживаемые выражения отклоняются без изменения данных.
- `ID` генерируется как максимальный текущий ID плюс один, для пустой таблицы —
  `1`. Передавать ID в `insert` и менять через `update` нельзя; фильтровать по нему
  можно. После удаления максимального ID его повторное использование допустимо.
- При отсутствии совпадений `update` и `delete` выводят
  `Подходящие записи не найдены.` Пустой результат `select` сохраняет заголовки.

## Хранение метаданных и данных

Структура таблиц сохраняется в `db_meta.json` в **текущей рабочей директории**:

```json
{
  "users": ["ID:int", "name:str", "age:int", "is_active:bool"]
}
```

Отсутствующий файл означает пустую базу. После успешного создания или удаления
структура сразу сохраняется, поэтому следующий запуск из той же директории
видит изменения. Другой рабочий каталог означает отдельную базу.

Строки хранятся отдельно в `data/users.json`:

```json
[
  {"ID": 1, "name": "Sergei", "age": 28, "is_active": true}
]
```

Директория `data/` создается автоматически. Новая таблица получает пустой файл;
отсутствующий файл также читается как пустая таблица. После успешных изменений
данные сразу сохраняются. Удаление таблицы удаляет и ее строки; повторное
создание начинает с пустой таблицы. Повторное создание существующей таблицы
отклоняется и не очищает строки.

В именах файлов без изменений сохраняются только `a-z`, `0-9`, `_` и `-`.
Остальные байты UTF-8 кодируются как `%XX`: таблица `Users` хранится в
`data/%55sers.json`, `active users` — в `data/active%20users.json`.
Это сохраняет различие регистра на macOS и исключает выход из каталога данных.

Некорректные команды не меняют файл. Запись выполняется через временный файл
с последующей заменой, чтобы ошибка записи сохранила предыдущую версию.
Поврежденный JSON, неверная структура метаданных или строк и ошибки файловой системы
завершают программу с сообщением и кодом `1`; успешный выход имеет код `0`.
Проверяются все обязательные поля, точные типы и положительные уникальные ID.
`db_meta.json` и `data/` исключены из Git. Одновременная запись из нескольких
процессов на этом этапе не поддерживается.

## Проверка качества и сборка

```sh
uv run python -m unittest discover -s tests -v
uv run ruff check .
uv run ruff format --check .
uv build
uvx twine check dist/*
```

Сборка создает wheel и исходный архив в `dist/`. Twine проверяет метаданные
локально; публикация на PyPI не требуется.

## Установка собранного пакета

```sh
uv tool install dist/primitive_db-0.3.0-py3-none-any.whl
database
```

Это устанавливает команду в отдельное окружение инструмента. Если каталог
исполняемых файлов отсутствует в `PATH`, выполните `uv tool update-shell`
и перезапустите терминал. Для повторной установки используйте:

```sh
uv tool install --force dist/primitive_db-0.3.0-py3-none-any.whl
```

## Текущий этап

Выполнены разделы 1–3: устанавливаемый пакет, цикл команд через `prompt`,
управление схемами таблиц, полный CRUD и хранение в JSON. Вывод строк оформлен
через PrettyTable. Текущая версия пакета — `0.3.0`.
Начальная версия с сообщением `DB project is running!` сохранена в истории Git.

- `src/primitive_db/__init__.py` — пустой маркер пакета.
- `src/primitive_db/main.py` — точка входа с шебангом и функцией `main()`.
- `src/primitive_db/engine.py` — справка, разбор команд и цикл программы.
- `src/primitive_db/core.py` — создание и удаление таблиц, CRUD-функции.
- `src/primitive_db/schema.py` — общие проверки схем, условий и строк.
- `src/primitive_db/parser.py` — разбор CRUD-команд и типизированных литералов.
- `src/primitive_db/utils.py` — загрузка и сохранение JSON.
- `tests/` — проверки через стандартный `unittest`, без новых зависимостей.
- `pyproject.toml`, `.python-version`, `uv.lock` — настройки и зависимости.
- `.gitignore` — исключения для окружения, кешей и результатов сборки.

Репозиторий: https://github.com/zlexc/py_hw2.
